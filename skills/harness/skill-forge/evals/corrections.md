# Corrections

## 2026-11-10: experimenting before creating blocked new skills

- Prompt: the author wanted skills for a software factory (agents triggered by issue, alert or clock) and the plan had to start with a two-week baseline and a design session only to produce the observed failure the skill demanded.
- What happened: the six eval-first steps (observed failure, three scenarios, baseline, then the first line) made the experiment so large that the skills were never started. The repo's history showed improvements came from corrections in use and reference gaps, not from the evals.
- What should have happened: a draft born from one or two real runs, improved from each correction, with the full baseline at promotion.
- Lesson (confirmed by the author): rigour grows with the status; evals accumulate from use instead of gating the first draft.
- Scenario: ids 1, 2 and 6 rewritten or added for the phased method.
